01 — 產品概念

一句話：把每一場跨語言會議，變成一份可搜尋的中文紀錄

使用者打開網頁（或桌面圖示）、按下錄音，Live Minutes 就開始把說話內容即時轉成文字、翻成繁體中文、標出是誰在說；散會後自動生成摘要、決議與待辦，全程不需要安裝任何 App。

即時聽打 + 語者分離

Deepgram 串流辨識，逐句上字幕並標記「發言者 1／2／3」，會議中就能回看誰說了什麼。

英↔繁中 雙語字幕

DeepL 把英文（或多語）轉成道地繁體中文，英文原句在上、中文在下，看得懂也對得上。

AI 自動會議紀錄

散會即觸發 Gemini 2.5 Flash，讀完整逐字稿後輸出摘要、決議事項、待辦（含負責人）與討論主題。

  1. 開始錄音
    手機瀏覽器透過 getUserMedia 取得麥克風，以 AudioWorklet 擷取 16kHz PCM 音訊。
  2. 即時辨識
    音訊串流送往 Deepgram，回傳帶標點、帶語者標籤的逐句文字（含 interim 即時預覽）。
  3. 即時翻譯
    每句「定稿」後才送 DeepL 翻成繁中，避免逐字翻造成閃爍與額度爆量。
  4. 即時儲存 & 跨裝置
    逐句寫入 Supabase；透過 Realtime 廣播讓另一支手機／平板同步看到字幕。
  5. 生成紀錄
    按下「結束會議」→ Vercel 函式把完整逐字稿丟給 Gemini → 產生結構化繁中會議紀錄存回 Supabase。
02 — 技術可行性評估

整體可行，但有一個「會讓原始設計無法運作」的關鍵問題

你的概念方向完全正確，選用的服務也都恰當。但原圖把「WebSocket Relay」放在 Vercel 上——這是行不通的，必須改成讓瀏覽器直連 Deepgram。這一點修正後，其餘全部成立。

8.5
/ 10 可行性

結論：值得做，且能在免費額度內跑起來

把音訊改為「瀏覽器 → Deepgram 直連」後，Vercel 只需負責靜態網頁 + 幾支輕量 Serverless Function（發臨時金鑰、翻譯代理、生成紀錄）。資料庫用 Supabase（可透過 Vercel Marketplace 佈建）。唯一需要留意的是 Deepgram 的 US$200 為一次性額度、以及 iOS 背景錄音限制。

四個必須知道的重點

阻斷級Vercel 不能跑 WebSocket 伺服器

Serverless／Edge Function 是「請求→回應」模型，沒有常駐行程可以維持長連線的音訊串流。原圖的「WebSocket Relay on Vercel」無法實作。

解法：瀏覽器用 Deepgram 官方 SDK 直連 wss://api.deepgram.com；Vercel 只出一支函式核發 Deepgram 的臨時短效金鑰（不外洩主金鑰）。延遲更低、更省、也真的能跑。

留意DeepL 若「逐字翻」會爆額度

Deepgram 的 interim 結果每秒更新多次，若每次都送 DeepL，免費 50 萬字/月會在數小時內用光，還會閃爍。

解法：只翻 is_final 的定稿句；英文即時串流、中文晚半句補上。UX 反而更自然，額度也撐得久。

留意iOS 背景／鎖屏會中斷錄音

iOS Safari 在鎖屏或切到背景時會暫停音訊擷取，一場會議錄到一半斷掉是真實風險。MediaRecorder 在 iOS 的格式支援也較零散。

解法：用 Wake Lock API 保持螢幕不睡、明確提示「請勿鎖屏」；擷取改用 AudioWorklet 直送 PCM，跨平台最穩。

留意Deepgram 免費是「一次性」US$200

不是每月重置。串流辨識約 US$0.0046–0.0077/分鐘，US$200 大約可撐數百小時，但用完就要付費，屬「成本懸崖」。

解法：MVP 可先用免費的瀏覽器 Web Speech API 驗證流程（缺點：無語者分離）；正式再切 Deepgram。長期把 ASR 供應商做成可抽換。

成立其餘元件都很適配，且都在免費級距

Vercel（靜態 + 函式）、Supabase（Postgres + Realtime，可跨裝置同步）、Gemini 2.5 Flash（每場會議一次呼叫、100 萬 token 脈絡足以吃下整份逐字稿）——三者的免費額度對「個人／小團隊」用量綽綽有餘。DeepL 繁中品質在 zh-TW 也優於多數免費翻譯。

03 — 修正後的系統架構

音訊直連、Vercel 只做輕量代理

下圖是可實作的版本。關鍵差異：音訊不經過 Vercel，而是瀏覽器直連 Deepgram；文字翻譯與紀錄生成才走 Vercel 的短請求函式。

原始構想的問題點

手機 → Vercel WebSocket Relay（常駐長連線） ✗ → Deepgram  —  Vercel 無常駐程序，長連線音訊串流做不到。

為什麼直連 Deepgram？

省掉一台常駐伺服器、延遲更低、也避開 Vercel 的長連線限制。金鑰安全由「臨時短效 token」保證，主金鑰永遠留在後端。

跨裝置怎麼做？

錄音的手機把逐句字幕寫進 Supabase，其他裝置訂閱同一場會議的 Realtime 頻道，即可同步顯示，無需自建 WebSocket。

散會如何觸發？

前端按「結束」呼叫 /api/minutes；或用 Supabase Edge Function / Database Webhook 在 session 標記結束時自動生成，兩種都可。

05 — UI / UX 設計

三個核心畫面：開始 → 即時字幕 → AI 紀錄

以手機直式為主。錄音時單手可操作、字幕以「中文為主、英文為輔」的雙層排版；紀錄頁把 AI 產出拆成可掃視的區塊。以下為高擬真示意（含實際範例內容）。

  • 中文為主的雙層字幕：繁中字級大、權重高；英文原句作輔助對照，兼顧「看得懂」與「對得上」。
  • 定稿才翻譯的節奏：英文即時串流、中文晚半句補上，既省 DeepL 額度、也避免翻譯閃爍。
  • 語者以顏色編碼：發言者 1–6 各有專屬色，深淺主題下皆維持可辨識對比。
  • 錄音態的安全感：常駐 LIVE 徽章、計時器與聲波動畫，並提示「請勿鎖屏」以規避 iOS 背景中斷。

成本控制策略

  • 把 ASR 供應商抽象成介面：Deepgram 額度用罄可切 Web Speech API（免費）或其他供應商。
  • 只翻定稿句 + 去重，DeepL 字元數可壓到原本的一小部分。
  • Gemini 每場會議僅呼叫一次；長逐字稿可先做重點抽取再摘要，控制 token。
  • 閒置自動停止錄音與辨識，避免額度空轉。
09 — 下一步

建議的啟動順序

1 · 環境建立 Vercel 專案與 GitHub repo、佈建 Supabase（可經 Vercel Marketplace）、申請 Deepgram / DeepL / Gemini 金鑰。
2 · Phase 0做出可安裝的 PWA 骨架 + Web Speech API 即時字幕，先在 iOS/Android 實機驗證錄音與 Wake Lock。
3 · 決策點確認 ASR 用 Deepgram（品質＋語者分離）；確認翻譯用 DeepL 或改由 Gemini 一併處理。
4 · 資料模型定義 sessions、utterances（含 speaker、原文、譯文、時間戳）、minutes 三張表。
5 · 視覺若要精準套用你分享的 Claude 設計，提供 claudeusercontent.com 的匯出連結或截圖，我即以現有 token 系統對齊。

這個產品可行、且能免費起步。只要把「Vercel WebSocket Relay」換成「瀏覽器直連 Deepgram + Vercel 輕量函式」，你的原始構想其餘部分都能照做。需要的話，我可以直接依這份計劃書開始把 Phase 0 的程式建起來。
