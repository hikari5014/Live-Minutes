01 — 產品概念

一句話：把每一場跨語言會議，變成一份可搜尋的中文紀錄

使用者打開網頁（或桌面圖示）、按下錄音，Live Minutes 就開始把說話內容即時轉成文字、翻成繁體中文、標出是誰在說；把連結傳給同事，對方就能即時同看；散會後自動生成摘要、決議與待辦——全程不需要安裝任何 App。

即時聽打 + 語者分離

Deepgram 串流辨識，逐句上字幕並標記「發言者 1／2／3」，會議中就能回看誰說了什麼。

英↔繁中 雙語字幕

DeepL 把英文（或多語）轉成道地繁體中文，英文原句在上、中文在下，看得懂也對得上。

AI 自動會議紀錄

散會即觸發 Gemini 2.5 Flash，讀完整逐字稿後輸出摘要、決議事項、待辦（含負責人）與討論主題。

  1. 開始錄音
    手機瀏覽器透過 getUserMedia 取得麥克風，以 AudioWorklet 擷取 16kHz PCM 音訊。
  2. 即時辨識
    音訊經 Cloudflare Durable Object「房間」中繼給 Deepgram，回傳帶標點、帶語者標籤的逐句文字。
  3. 即時翻譯
    每句「定稿」後才送 DeepL 翻成繁中，避免逐字翻造成閃爍與額度爆量。
  4. 房間廣播 · 跨裝置
    字幕由該場會議的 Durable Object 即時廣播給房間內所有裝置；朋友用分享連結加入即可同看。
  5. 生成紀錄
    按下「結束會議」→ Cloudflare Worker 把完整逐字稿交給 Gemini → 結構化繁中紀錄存入 D1，房間連結變成回看頁。
02 — 技術可行性評估

可行——而且改用 Cloudflare 後，原本卡住的「即時中繼」反而變成優勢

你的概念方向完全正確。唯一要修正的是「WebSocket 中繼要放在哪」：Vercel 的 serverless 無法維持長連線，但 Cloudflare Durable Objects 原生支援持久 WebSocket，還天生適合「一場會議一個房間」——中繼、跨裝置同步、分享連結一次到位。

結論：全 Cloudflare 一站式，能免費起步且原生支援即時房間

前端放 Cloudflare Pages；每場會議用一個 Durable Object 當「中繼 + 房間」，把音訊轉給 Deepgram 並把字幕廣播給所有裝置；翻譯與紀錄用 Workers，資料存 D1 / R2。程式碼放 GitHub，每次 push 自動部署。唯一長期變數是 Deepgram 的 US$200 一次性額度與 iOS 背景錄音限制。

四個必須知道的重點

關鍵解法Durable Objects = WS 中繼 + 每場會議房間

Vercel serverless 沒有常駐行程、維持不了長連線，所以放不了 WS 中繼。Cloudflare Durable Objects 原生支援持久 WebSocket（還有 Hibernation，閒置不計費），而且「一個物件 = 一個房間」，天生適合會議與分享連結。

你原本想要的 Relay 方向是對的——只是要放在能跑長連線的 Cloudflare，而不是 Vercel。

留意DeepL 若「逐字翻」會爆額度

Deepgram 的 interim 結果每秒更新多次，若每次都送 DeepL，免費 50 萬字/月會在數小時內用光，還會閃爍。

解法：只翻 is_final 的定稿句；英文即時串流、中文晚半句補上。UX 反而更自然，額度也撐得久。

留意iOS 背景／鎖屏會中斷錄音

iOS Safari 在鎖屏或切到背景時會暫停音訊擷取，一場會議錄到一半斷掉是真實風險。MediaRecorder 在 iOS 的格式支援也較零散。

解法：用 Wake Lock API 保持螢幕不睡、明確提示「請勿鎖屏」；擷取改用 AudioWorklet 直送 PCM，跨平台最穩。

留意Deepgram 免費是「一次性」US$200

不是每月重置。串流辨識約 US$0.0046–0.0077/分鐘，US$200 大約可撐數百小時，但用完就要付費，屬「成本懸崖」。

解法：MVP 可先用免費的瀏覽器 Web Speech API 驗證流程（缺點：無語者分離）；正式再切 Deepgram。長期把 ASR 供應商做成可抽換。

成立其餘元件都很適配，且都在免費級距

Cloudflare Pages（前端 + 公開網址）、Workers（短請求函式）、Durable Objects（房間/中繼）、D1（SQLite 儲存）、R2（檔案）——全在免費方案內；GitHub 負責原始碼與自動部署；Gemini 2.5 Flash（每場一次呼叫、1M token 脈絡足以吃下整份逐字稿）與 DeepL 繁中翻譯也都免費起步。而且觀看者只是接收廣播，不會多花 Deepgram 辨識費用。

03 — 系統架構（GitHub → Cloudflare）

程式碼放 GitHub、後端全在 Cloudflare

GitHub 存原始碼並在 push 時觸發部署；Cloudflare 一站包辦前端、函式、即時房間與資料庫。音訊經「房間」（Durable Object）中繼給 Deepgram，字幕再廣播回房間內所有裝置。

✗ Vercel：WS 中繼放不了

Serverless／Edge 是「請求→回應」，沒有常駐程序維持長連線的音訊串流，做不了中繼與房間。

✓ Cloudflare：Durable Object 天生適合

原生持久 WebSocket + Hibernation 省費，「一物件一房間」同時解決中繼、跨裝置同步與分享連結。

為什麼用 Durable Objects？

它能維持常駐長連線、「一物件一房間」，天然適合會議：中繼音訊、保存當下狀態、把字幕廣播給所有人；WebSocket Hibernation 讓沉默時段不計費。

Deepgram 金鑰怎麼保護？

音訊經房間（DO）中繼，主金鑰完全留在 Cloudflare 端、永不下放到瀏覽器；也可改用臨時金鑰讓裝置直連，兩種都支援。

散會如何觸發 & 儲存？

前端按「結束」呼叫 Worker /api/minutes → Gemini 生成紀錄 → 存入 D1；逐字稿與（選用的）錄音檔放 D1／R2，房間連結即成回看頁。

04 — 會議房間與分享連結

每場會議一個房間、一條連結，點開就一起看

這是「跨裝置 / 分享給朋友隨開即用」的核心機制：每建立一場會議，就生出一個 Durable Object 房間 與一條 分享連結（例如 liveminutes.app/m/ab12cd）。主持人錄音、其他人點連結加入，字幕即時同步——無需安裝、可選免登入。

  1. 建立會議 → 生出房間
    系統配一個房間 ID 與分享連結；此房間即該場會議的 Durable Object。
  2. 主持人開始錄音
    主持裝置以 WebSocket 連進房間，音訊在房間內中繼給 Deepgram 辨識。
  3. 朋友點連結加入
    用手機/電腦瀏覽器打開連結即進入房間，可選免登入或設密碼、設有效期。
  4. 字幕即時廣播
    房間把雙語字幕與語者標籤廣播給所有在線裝置——只辨識一次、眾人同看。
  5. 散會 → 連結變回看頁
    結束後生成 AI 紀錄存入 D1；同一條連結即成該場的逐字稿與紀錄頁。

省成本觀看者不佔用額外辨識額度

房間只辨識「主持人音訊」一次，字幕以廣播分送。多 10 個朋友觀看，Deepgram 費用不變——增加的只是 Durable Object 的連線數（免費額度內）。

留意費用與權限算主持人

公開連結被使用時，Deepgram／DeepL／Gemini 用量記在主持人金鑰。建議支援：連結密碼、有效期、以及「僅觀看（唯讀）」模式，必要時再加登入。

主持人（錄音端）

擁有麥克風控制、開始/結束、語者命名與權限設定；音訊只從這端進房間辨識。

觀看者（唯讀端）

點連結即進房間，同步看到雙語字幕與語者；不需麥克風、不佔辨識額度，散會後可回看紀錄。

06 — UI / UX 設計

三個核心畫面：開始 → 即時字幕 → AI 紀錄

以手機直式為主。錄音時單手可操作、字幕以「中文為主、英文為輔」的雙層排版；紀錄頁把 AI 產出拆成可掃視的區塊。（分享/房間畫面見上一節。）以下為高擬真示意，含實際範例內容。

  • 中文為主的雙層字幕：繁中字級大、權重高；英文原句作輔助對照，兼顧「看得懂」與「對得上」。
  • 定稿才翻譯的節奏：英文即時串流、中文晚半句補上，既省 DeepL 額度、也避免翻譯閃爍。
  • 語者以顏色編碼：發言者 1–6 各有專屬色，深淺主題下皆維持可辨識對比。
  • 錄音態的安全感：常駐 LIVE 徽章、計時器與聲波動畫，並提示「請勿鎖屏」以規避 iOS 背景中斷。

成本控制策略

  • 觀看者不加辨識費：房間只辨識主持人音訊一次，字幕以廣播分送，加人不加 Deepgram 成本。
  • 把 ASR 供應商抽象成介面：Deepgram 額度用罄可切 Web Speech API（免費）或其他供應商。
  • 只翻定稿句 + 去重，DeepL 字元數可壓到原本的一小部分。
  • Durable Objects 用 WebSocket Hibernation，沉默時段不計運行費；閒置自動停止錄音與辨識。
  • Gemini 每場僅呼叫一次；長逐字稿可先重點抽取再摘要，控制 token。

建議的啟動順序

1 · 環境建立 GitHub repo，接上 Cloudflare Pages 自動部署；建立 Workers 與 Durable Objects 綁定、D1 資料庫；申請 Deepgram / DeepL / Gemini 金鑰並存為 Cloudflare Secrets。

3 · 房間雛形建立 Durable Object 房間 + /m/:id 分享連結，讓第二支手機能點連結加入、同看廣播字幕。
4 · 資料模型在 D1 定義 sessions、utterances（含 speaker、原文、譯文、時間戳）、minutes 三張表；房間即時狀態放 Durable Object。
5 · 視覺若要精準套用你分享的 Claude 設計，提供 claudeusercontent.com 的匯出連結或截圖，我即以現有 token 系統對齊。

一句話總結

這個產品可行、能免費起步、且能一鍵分享給朋友隨開即用。把後端放在 Cloudflare（Pages + Workers + Durable Objects + D1/R2）、程式碼放 GitHub 自動部署——你原本想要的「WebSocket 中繼」在這裡不但能跑，還順勢變成「每場會議一個房間 + 分享連結」。需要的話，我可以直接依這份計劃書開始把 Phase 0 建起來。
